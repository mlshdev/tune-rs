### Latest completion — SOCKS5 UDP ASSOCIATE parity (2026-10-19)

Continuation of the rewrite (authorized "continue the whole rewrite"). Closed the SOCKS5 gap honestly recorded in "Next concrete actions": TCP-only CONNECT, no UDP ASSOCIATE, no client CIDR allowlist.

- `src/socks5.rs`: SOCKS5 UDP ASSOCIATE per RFC 1928. A second socket bound beside the TCP listener (same address) receives client datagrams. The TCP control request registers an association — explicit client endpoint, or lazy binding to the first observed datagram source when DST.ADDR is 0.0.0.0 (domain ATYP is ignored for matching, as in gluetun). `SOCKS5_ALLOWED_CIDRS` filters datagram source IPs. Per-(client,destination) flow sockets are `connect()`ed and their pump tasks re-wrap replies with a SOCKS header; flows are bounded (512), swept after 60 s idle, and all aborted on tunnel status change. Fragmented or malformed datagrams are dropped; domain destinations resolve in-container. The reply advertises the configured override or the control connection's local IP with the datagram socket's port. Closing the TCP control connection (or tunnel stop) unregisters via drop guard. The UDP loop lives outside the connection `JoinSet` so status changes abort connections + flows but **not** the relay task — a stop→start cycle keeps UDP working (regression-proven).
- `src/config.rs`: `Socks5Settings` gains `allowed_cidrs` (validated parse) and `udp_advertised_address` (validated: reachable unicast IP, nonzero port). `SOCKS5_ENABLED` accepted as gluetun-compatible enable switch, lower precedence than `SOCKS5`. Validation runs at env load and `Server::bind`.
